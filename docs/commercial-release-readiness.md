# Kiana Commercial Release Readiness

## Workflow Transition And Completion Gate

- `kiana tasks workflow advance` now resolves only a unique edge from the persisted current node, requires bounded workflow-relative regular-file evidence, records SHA-256, and appends `gate_evaluated`, `node_exited`, and `node_entered` under one writer lease before state projection.
- `kiana tasks workflow complete` requires the `completed` terminal node and revalidates an immutable same-run VerificationPacket, its Evidence Ledger references, counts, `verification_completed` event, and `final_status=pass` before appending `workflow_completed`.
- The JSON contracts are pinned by `kiana-workflow-transition.v1.schema.json` and `kiana-workflow-completion.v1.schema.json`. Six integration tests cover legal progression, invalid decisions, missing/placeholder evidence, absolute and parent paths, directories, symlink escape, duplicate scalar options, non-terminal completion, missing/foreign/tampered/non-pass packets, and idempotent same-packet retry.
- Package lifecycle smoke must execute the unpacked installed binary through a real DAG path, generate a VerificationPacket with `kiana validate`, complete the run, and verify its authenticated EventLog. This proves the local mechanism; it does not fabricate the actual release proof, clean tracked-tree evidence, external signatures, channels, hosted services, or customer acceptance.

## Workflow Recovery Integrity Gate

- Bounded Swarm active recovery journals are authenticated with revisioned HMAC records linked by `previous_record_sha256` and freshness-anchored in the authenticated Workflow EventLog.
- Completed recovery journals are committed as immutable `recovery_journal_archive` artifacts; archive mutation, missing archive events, and deleted archive files fail verification.
- `kiana tasks workflow integrity verify --json <run_id>` includes `recovery_integrity` using schema `kiana.swarm-recovery-integrity-report.v1` and a `kiana.workflow-release-binding.v1` object that binds the proof to the exact run, workflow, Git HEAD, cached diff, worktree diff, and porcelain-v2 status. Commercial verification strengthens the status digest with every untracked file's path, Git-style mode, size, and content SHA-256; changing an untracked file without renaming it therefore invalidates the proof.
- `kiana release workflow-proof --json --run-id <run_id>` stages that same verified WorkflowRun proof to `dist/proofs/workflow/recovery-integrity.json` by default and emits the exact environment bindings required by the commercial blocker report, so release owners do not need to hand-assemble `KIANA_RELEASE_WORKFLOW_RUN_ID` and `KIANA_WORKFLOW_RECOVERY_INTEGRITY_PROOF_FILE`. `--latest-completed` is a safer local staging shortcut: it only selects the newest already-completed WorkflowRun from `.kiana/workflows`, records `selection.mode=latest_completed`, and still verifies integrity before writing the proof file.
- The release binding also records Workflow status/current node/final event sequence/final event kind and SHA-256 digests for `state.json` plus `eventlog.jsonl`; CLI generation checks state/EventLog sequence consistency before emitting proof.
- Commercial check `workflow.recovery-integrity` reads `dist/proofs/workflow/recovery-integrity.json` by default, requires an explicit `KIANA_RELEASE_WORKFLOW_RUN_ID`, independently reloads the selected Workflow artifacts and current Git binding, and rejects missing/invalid JSON, wrong-run, stale Workflow/Git proof, non-`completed` runs, a final event other than `workflow_completed`, empty/partially verified EventLogs, non-verified integrity status, legacy journals, unanchored tails, count gaps, mismatches, invalid key IDs, and sensitive fields such as `secret_hex`.
- The proof contract and fixture tests are implemented locally. The repository does not currently contain a staged proof from the actual release workflow, so the live blockers report correctly keeps this check in `blocking` state until a release owner generates it from the selected signed run.

## Commercial Blocker Action Plan

- `kiana release blockers --json` and `scripts/commercial-release-blockers-report.sh --json` include a pinned `action_plan` object with schema `kiana.commercial-release-action-plan.v1` inside the `kiana.commercial-release-blockers.v1` report.
- The action plan mirrors only currently blocking checks, splits them into `local_actions` and `external_actions`, groups them again under `actions_by_resolution_scope`, and preserves each action's owner, owner status, resolution scope, required action, acceptance artifacts, verification commands, environment variables, paths, and handoff notes.
- `scripts/commercial-release-blockers-report.sh --handoff-md <path>` renders the same blocker set for human owner assignment, while the JSON `action_plan` remains the machine-readable source for project-board import, PMP-style assignment, and release follow-up automation.
- This does not satisfy external release evidence by itself. It makes the remaining commercial gaps assignable and auditable without converting pending signing, distribution, live-service, acceptance, or dirty-tree blockers into passed checks.

### EventLog/state 崩溃恢复子门禁

- 本地 runtime 已处理一种可证明安全的 crash window：EventLog 已完整、连续并通过 HMAC 链验证，但进程在 `state.json` 更新前退出。
- 自动修复要求旧 state 与其 `last_event_seq` 对应的 EventLog 历史前缀逐字段一致，覆盖 schema、目录/run 身份、workflow 身份、请求、input/profile、审批配置、status/current node、checkpoint、pending approvals、created/updated timestamps。任何篡改、state 超前或 EventLog 损坏均返回 `blocked`。
- 修复发生在 writer lease 内，写回采用同目录临时文件、flush、file sync、原子替换；Unix 追加父目录 sync，Windows 使用 `MoveFileExW(...REPLACE_EXISTING | ...WRITE_THROUGH)`。命令层保留 `repaired` 审计状态，同时允许 workflow、swarm、validate 和 evidence verify 继续。
- 本地证据包括 `kiana-tasks/tests/workflow_runtime.rs` 的合法 lag、latest-run、身份/请求/checkpoint/approval/timestamp 篡改测试，以及 `kiana-commands` 的 continue、validate、evidence 回归。真实 Windows/macOS release runner 的断电与文件系统故障注入仍需要外部平台证明，不能由本地 Linux 测试代替。

## Bounded Swarm Worker Process Identity Gate

- Linux Bounded Swarm worker state now uses `kiana.swarm-worker-state.v2` with a nested `kiana.swarm-process-identity.v1` record binding PID, PGID, `/proc/<pid>/stat` start-time, and command SHA-256 provenance. Command digest is retained for audit provenance only; process continuity is decided by PID/PGID/start-time identity.
- `swarm status` and `swarm monitor` now emit top-level `kiana.swarm-process-identity-backend.v1`, so downstream tools can read whether the current platform is safe for start/monitor/cancel without scraping logs. Linux reports `linux_procfs`; non-Linux reports `unsupported_platform` with `process_identity_backend_not_implemented` and fails closed instead of implying support.
- `status`, `monitor`, and `cancel` fail closed when identity is missing, mismatched, exited unexpectedly, or unavailable. `cancel` performs a two-phase preflight across every selected non-terminal worker before signaling, so one suspicious worker prevents partial termination side effects.
- Focused local evidence is provided by `kiana-commands/src/swarm_process_identity.rs`, `kiana-commands/tests/swarm_command.rs`, `docs/schemas/kiana-swarm-process-identity-backend.v1.schema.json`, `docs/schemas/kiana-swarm-worker-state.v2.schema.json`, and `scripts/schema-contract-smoke.sh`.
- This gate proves local Linux procfs PID-reuse protection and a machine-readable platform boundary for worker lifecycle control. It does not prove Windows/macOS safe process identity backends, external orchestrator supervision, or customer production incident handling.

## Bounded Swarm Automatic Retry Gate

- `swarm monitor` now performs bounded automatic retry only for clean `worker_failed` exits where the worker produced no file changes, no scope deviations, no project baseline drift, and the current attempt is below `max_attempts`.
- Failed attempt outputs are archived under `workers/<dispatch>/<task>/attempts/<attempt>/` with `attempt-summary.json` before the next attempt starts; final `kiana.swarm-result-packet.v1` is emitted only after success or retry exhaustion.
- Non-retryable terminal states remain fail-closed: `cancelled`, `scope_violation`, `budget_exhausted`, `timeout`, `lost`, identity mismatch, project drift, and failures with changed files are not restarted automatically.
- Focused evidence is `swarm_monitor_retries_worker_failed_until_success` plus the existing scope/output/command-budget regression in `kiana-commands/tests/swarm_command.rs`.

## Bounded Swarm Worker Health Reporting Gate

- `swarm status` and `swarm monitor` now emit `kiana.swarm-worker-health.v1` for every worker row, with normalized `state`, `reason`, `next_action`, process identity status, retry attempt counters, budget remaining fields, and scope/project drift counters.
- Healthy running workers, retrying workers, completed workers, and terminal attention-required workers can be distinguished without scraping stdout, stderr, or human text.
- Focused evidence is in `swarm_monitor_retries_worker_failed_until_success` and `swarm_monitor_classifies_scope_output_and_command_budget_violations`, and release preflight checks the health contract marker.

## Bounded Swarm Worker Telemetry Gate

- `swarm monitor` now writes `kiana.swarm-worker-telemetry.v1` into each terminal `kiana.swarm-result-packet.v1`, while retaining the legacy top-level `commands_run` array for compatibility.
- The structured telemetry object records whether runner telemetry existed, command count used for budget enforcement, parsed command names, invalid non-string command entries, raw telemetry SHA-256, and parser notes.
- Focused evidence is in `swarm_monitor_commits_idempotent_result_packets_for_completed_workers`, `swarm_monitor_classifies_scope_output_and_command_budget_violations`, `docs/schemas/kiana-swarm-worker-telemetry.v1.schema.json`, and `scripts/schema-contract-smoke.sh`.
- This gate proves local worker telemetry aggregation and budget accounting. It does not prove external worker telemetry collection, hosted observability, or cross-machine swarm supervision.

## Local Structured Memory Gate

- `kiana memory append` now keeps the legacy `memory.md` behavior while also appending schema-pinned `kiana.memory-record.v1` JSONL records under `$KIANA_HOME/memory/events.jsonl` with explicit `kind`, `source`, redacted text, stable local id, `redaction_count`, and timestamp fields.
- `kiana memory append` redacts obvious local secrets before persistence, including `token=`, `password=`, `secret=`, `api_key=`, `sk-`, `xoxb-`, and `ghp_` token shapes. `kiana memory status --json` emits aggregate redaction counts, and `kiana memory search --json <query>` includes per-hit `redaction_count` without exposing the original secret.
- `kiana memory status --json` emits `kiana.memory-status.v1`, and `kiana memory search --json <query>` emits `kiana.memory-search.v1`. Corrupt JSONL records fail closed with line-number evidence instead of being silently ignored or treated as empty memory.
- Focused local evidence is provided by `kiana-commands/src/memory.rs`, `docs/schemas/kiana-memory-record.v1.schema.json`, `docs/schemas/kiana-memory-status.v1.schema.json`, `docs/schemas/kiana-memory-search.v1.schema.json`, `cargo test -p kiana-commands memory --locked --offline --no-fail-fast`, and `scripts/schema-contract-smoke.sh`.
- This gate proves local deterministic structured memory storage, lexical retrieval, and basic secret-shape redaction before persistence. It does not prove automatic session mining, semantic embeddings, vector databases, cross-device sync, team access control, complete PII classification, or stale-memory invalidation.

## Offline Eval Harness Gate

- `kiana eval run --suite <file> --baseline <file> --json --fail-on-failure` provides a read-only, deterministic RuntimeEvent replay gate with strict suite/baseline/report schemas, stable SHA-256 bindings, bounded resource limits, path-containment enforcement, typed findings, baseline-regression failure semantics, and non-zero failure behavior. Usage events require complete non-negative integer input/output token counts; missing or malformed token fields are rejected rather than reported as zero-cost execution.
- The release archive includes `docs/eval/fixtures/`; package lifecycle smoke runs the unpacked binary against `basic-runtime-suite.json` plus `basic-runtime-baseline.json`, and release smoke runs the same suite/baseline pair against both the release binary and the installed binary.
- Focused local evidence is provided by `kiana-commands/tests/eval_command.rs`, `kiana-entrypoints/tests/cli_eval.rs`, `scripts/schema-contract-smoke.sh`, `scripts/release-smoke.sh`, and `scripts/package-lifecycle-smoke.sh`.
- This gate proves the packaged offline event-evaluation and local baseline-regression contract. It does not prove real-model quality, external benchmark performance, fake-provider multi-turn agent behavior, production telemetry evaluation, or target-customer acceptance; those remain explicit commercial/product gaps rather than inferred success.
