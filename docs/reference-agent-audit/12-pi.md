## 端到端流程

```text
CLI args/stdin/@file
  → main mode/session selection
  → AgentSession.prompt
  → system prompt + context + tools
  → agent-core runAgentLoop
  → provider stream/SSE
  → assistant text or tool call
  → schema/prepare/validation
  → tool execution
  → tool_result message
  → next model step
  → retry/compaction/follow-up
  → agent_end
  → JSONL/TUI/RPC output
```

## Tool loop

- agent loop 依次处理 assistant stream、tool execution、tool result、next-step refresh 和 steering：`packages/agent/src/agent-loop.ts:95-143,163-275`。
- 截断的 assistant tool call 全部拒绝执行，生成错误 tool result：`agent-loop.ts:202-224,374-405`。
- 工具参数先 prepare/validate；unknown、parser、validation 和 hook 异常都变成 tool result：`agent-loop.ts:586-667`。
- 工具可串行或并行；并行执行后仍按模型调用顺序写回结果：`agent-loop.ts:408-553`。
- `tool.execute()` 支持 partial update；after hook 可改写结果；最终是带 toolCallId/name/content/details/usage 的 `toolResult`：`agent-loop.ts:670-790`。

## 工具与权限

默认工具包含 `read/bash/edit/write`：`core/sdk.ts:254-261`。源码没有默认逐工具审批；只有 extension 注册 `tool_call` hook 时才能 block/改写，未安装 hook 时 schema 校验后直接执行：`core/agent-session.ts:485-537`、`packages/agent/src/agent-loop.ts:619-660`。

Project trust 主要控制项目本地 settings/extensions/resources 的加载，不等价于每次 bash/edit/write 的运行时授权：`core/resource-loader.ts:380-402,1025-1039`。

Bash 终止整棵 process tree、限制输出并支持 timeout/abort；read 支持图片和 line/byte 截断；edit 保留 BOM/换行风格并返回 diff；write 写入 cwd 下路径；同文件 mutation 通过 queue 串行：`core/tools/bash.ts:88-190,322-462`、`read.ts:209-358`、`edit.ts:316-409`、`write.ts:187-274`、`file-mutation-queue.ts:32-61`。

## 优点

- JSONL append-only tree 支持 resume、fork、branch navigation 和 compaction projection。
- provider stream 统一转成 agent events；tool partial JSON、abort 和 truncated stream 有明确处理。
- 同文件 mutation queue 防止并发写交叉。
- tool result 顺序与模型调用顺序一致，错误也能回灌模型。
- CLI、TUI、RPC 和 batch 共享 AgentSession。

## 风险与缺口

- 默认没有逐工具/逐命令 approval；安全决策依赖 extension 或外部 sandbox。
- Session JSONL 包含 shell 输出、文件内容和图像数据，需要权限、保留和脱敏策略。
- Project trust 不等于工具执行授权。
- Provider/extension 多路径增加 policy 组合复杂度。

## 对 Kiana 的映射

- `AgentSession` → Kiana 应用级 AgentRuntime/SessionService。
- append-only tree → Kiana Session/Turn/Event ledger。
- `runAgentLoop` → KianaHarness 的模型/工具阶段。
- tool prepare/validate/execute/result → Kiana CapabilityRequest + Policy/Gate/Broker。
- extension hook → Kiana typed policy middleware，但危险能力不能依赖可选 hook。
- RPC print/TUI → Kiana thin transport adapters。
- compaction/fork → Kiana 后续 checkpoint/fork API。

Kiana 不应复制 Pi 的默认执行授权；应保留它的结构化 tool lifecycle、file mutation queue、abort lifecycle 和 JSONL tree，同时将 policy/approval 提升为不可绕过的 ControlPlane 规则。
