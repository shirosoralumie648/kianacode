## 重要决策清单

### 决策 1：工作区改动如何处理？

当前状态：281 个文件有改动，全部是注释。

选项：
- A. 立即 stash 全部，清理工作区 → 更新统计后，再从头处理
- B. 逐文件 commit（审查通过后），保留未通过的在工作区
- C. 等所有相关文件都审查通过后，一起大 commit

**推荐**：**选 B**
- 理由：注释改动通过审查就可以 commit，不需要等待全部完成
- 好处：减轻工作区压力，更清晰的 git 历史
- 缺点：commit 会比较频繁

**执行计划**：
```
每个文件流程：
1. Agent 完成注释
2. 格式检查（cargo fmt --check）
3. 编译检查（cargo check -p <crate>）
4. 独立质量审查
5. 审查通过 → git commit
6. 更新 ANNOTATION_TASK_MANIFEST.md
```

### 决策 2：Batch 3 Phase 1 的 9 个文件如果达标，下一步是什么？

选项：
- A. 立即启动质量审查 Agent，待审查通过后 commit
- B. 小休一下（5-10 min），等两个评审 Agent 都完成，再统一决策
- C. 先做 Phase 2 清理，等工作区清理后再处理 Phase 1 提交

**推荐**：**选 A**
- 理由：Phase 1 和评审是独立的并行任务，没必要等
- 好处：加快整体进度
- 缺点：同时多个 Agent 可能需要更多上下文

当前状态：dispatch.rs, approvals.rs 等已有注释改动，但需评审确认质量。

- B. 先 stash 这些改动，从头开始（重新开始注释）
- C. 等 Phase 1 完成后再处理 Phase 2

**推荐**：**选 A + 继续深度处理**
