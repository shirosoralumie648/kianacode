The optimized verifier may consolidate in-process work only after one successful `load_validated_manifest_bundle`/semantic validation. It must preserve each existing production obligation: checked current selector and evaluation time; 38 unique current repository identities; separately asserted official-source, reference, and target drift; the exact `integrity.evidence-expired` and `integrity.newer-failed-retest` corpus diagnostics; legacy inventory/ancestry/hash/current-head checks; generated views and compatibility output; and both checked-in public/reference diffs.

The handoff is a closed, versioned JSON interface. `scripts/capability_governance.py` owns `PRODUCTION_REPORT_SCHEMA = "kiana.capability-governance-production-report.v1"`, `PRODUCTION_REPORT_VERSION = "1.0"`, and one immutable ordered `PRODUCTION_CHECK_IDS` tuple. A report has exactly the top-level fields `schema`, `version`, `status`, `manifest_sha256`, `evaluation_time`, and `checks`; `schema` and `version` must equal those constants, `status` is exactly one of `pass` or `fail`, `manifest_sha256` is the canonical SHA-256 of the manifest actually loaded, and `evaluation_time` is the selected UTC evaluation timestamp. `checks` is an ordered array whose rows have exactly `id` and `status`; row status is exactly one of `pass`, `fail`, or `stale`. The immutable ID tuple, in this order, is `canonical-bundle`, `current-selector`, `evaluation-time`, `repository-identities-38`, `official-source-drift`, `reference-drift`, `target-drift`, `integrity.evidence-expired`, `integrity.newer-failed-retest`, `legacy-authority`, `generated-views`, `compatibility-output`, `public-baseline-diff`, and `repository-registry-diff`. The producer self-validates the report before writing it; the Bash consumer calls the same shared validator and accepts only top-level `pass` with one `pass` row for every and only those IDs. Unknown fields or IDs, missing or duplicate IDs, mismatched manifest/evaluation metadata, malformed values, stale rows, and any non-pass status are nonzero failures.

The cold-path regression is a fresh-process test, not a claim that an unprivileged test can globally evict the kernel page cache. Each sample starts a new public supervisor, bwrap sandbox, Bash worker, and isolated Python process, so no prior process can supply an in-memory validation result. The exact same checked-in test is rerun only after the verifier and shell changes, when it must require two consecutive actual `production` samples to finish within 25 seconds and preserve the fixed 30-second supervisor deadline, yielding at least five seconds measured headroom without network access.
