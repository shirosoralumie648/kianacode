<known_hot_spots>
From code inspection of verify_production_command (lines 463-610):

1. `deterministic_json_bytes(public_document)` is computed twice:
   - once inside `preflight_output_paths(args.public_diff.parent, {args.public_diff.name: deterministic_json_bytes(public_document)})`
   - once inside `write_or_check_outputs(..., {args.public_diff.name: deterministic_json_bytes(public_document)}, check=True)`
   Both calls serialize the same in-memory object. Caching the bytes eliminates the second serialization.

2. `deterministic_json_bytes(registry_document)` has the same double-computation pattern for the registry-registry-diff check.

3. `_production_diff_document` builds two large documents (public-baseline, repository-registry) from the bundle; both are fully computed before any check runs. Verify that no further redundant computation exists within this function.

4. If profiling reveals additional hot spots beyond (1) and (2), fix those too, subject to the constraints in <interfaces>.

Profiling method (no new deps): wrap `verify_production_command` call in a `cProfile.Profile()` context in a test double and record cumulative time per call. Use this to confirm (1)+(2) are the primary drivers before patching.
</known_hot_spots>
