<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Official source artifact -> public source index | Omitted or duplicated entries can hide published behavior. |
| Exclusion review -> capability coverage | A weak exclusion can relabel a missing required behavior as out of scope. |
| Verification fixture -> production CLI | A fixture can become an accidental alternate specification if production branches on it. |

## STRIDE Threat Register (ASVS L1)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-05-01 | Tampering | source mapping | high | mitigate | One-invariant post-implementation cases and exact duplicate diagnostics. |
| T-05-02 | Repudiation | exclusion | high | mitigate | Classification, rationale, evidence IDs, and review revision are mandatory. |
| T-05-03 | Spoofing | journey completeness | high | mitigate | Required IDs stay explicit and cannot be erased by exclusion. |
| T-05-04 | Tampering | implementation boundary | medium | mitigate | Plan 01-04 completion prerequisite and no fixture-name/case-ID production branches. |
</threat_model>
